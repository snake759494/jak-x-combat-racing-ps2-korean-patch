# 기술 설명

Jak X는 너티 독의 GOAL(Lisp) 엔진 게임입니다. 실행 파일(`SCUS_974.29`)은 커널뿐이고, 게임 코드와 데이터는 `CGO/`·`DGO/` 묶음 안의 GOAL 오브젝트로 들어 있습니다. 형식 해석에는 OpenGOAL 프로젝트(jak-project)의 공개 분석을 참고했습니다.

## 파일

| 파일 | 내용 |
| --- | --- |
| `TEXT/{n}COMMON.TXT` | 게임 텍스트 (`game-text-info`), n = 언어 0~11 |
| `TEXT/{n}SUBTIT.TXT` | 컷신 자막 |
| `CGO/GAME.CGO`, `CGO/ART.CGO` | 글꼴 텍스처 `tpage-12`(gamefont) 등. GAME.CGO에는 `font`·`font-h` 코드 오브젝트도 있음 |

언어 슬롯: 0 영어, 1 프랑스어, 2 독일어, 3 스페인어, 4 이탈리아어, 7 한국어 자리(영어 대체문), 8 러시아어, 9 포르투갈어, 나머지는 영어 사본. 게임이 어느 슬롯을 읽어도 한국어가 나오도록 12개 슬롯 모두를 같은 한국어 텍스트(언어 ID만 다르게)로 만들었습니다.

## CGO / DGO 압축 (oZlB)

`"oZlB"` + 풀린 크기(u32), 그 뒤 4바이트 정렬된 블록: 블록 크기(u32) + LZO1X 데이터. 크기가 0x8000 이상이면 무압축 0x8000바이트. 풀린 내용은 DGO(오브젝트 수 + 이름, 각 오브젝트: 크기·이름 0x40바이트 헤더 + 데이터, 16바이트 정렬).

`tools/dgo.py`의 `zlb_rebuild`는 바뀐 0x8000 블록만 `tools/lzoc.py`(LZO1X 압축기)로 다시 압축하고 나머지 블록은 원본 바이트를 그대로 씁니다. 무변경이면 원본과 바이트 단위로 같습니다.

## 게임 텍스트 (game-text-info)

GOAL 링크 오브젝트(v5 이전 형식, 0x80 헤더 + 데이터 + 링크 블록). 데이터:

```
+0  type tag   +4 length(항목 수)  +8 language-id  +12 group-name(string)
+16 dic-index(u32 배열, dic-data 안 오프셋)  +20 dic-data(1바이트 길이 + 바이트열 조각)
+24 text({u32 id, u32 index} 배열, id 오름차순)  +28 text-data
```

문자열 = `text-data[index]`의 조각 번호 목록. 첫 바이트 b: `b & 0x80`이면 번호가 2바이트, `b & 0x7f`가 조각 수(127이면 뒤에 255가 이어지는 가변 길이). 각 번호의 조각을 이어 붙이면 문자열.

`tools/txtbuild.py`는 원본 사전의 앞부분(문자 변환에 쓰이는 단일 문자 조각)을 그대로 두고 그 뒤에 단어 조각을 추가해 다시 만듭니다. 번역하지 않은 항목은 원본 레코드를 그대로 복사합니다. 링크 블록(포인터 재배치표, `game-text-info`·`string` 심볼 링크)도 새로 만듭니다. 공통 텍스트는 고정 힙(0x12800 B) 안에 들어가야 합니다(결과 62,496 B).

## 글꼴과 한글 출력

글꼴 텍스처 `tpage-12`는 4비트(PSMT4) 텍스처 6장입니다. 데이터는 폭 128의 PSMCT32 전송으로 VRAM에 올라가므로 `tools/tpage.py`가 GS 메모리 배치를 흉내 내 픽셀을 읽고 씁니다.

| 텍스처 | 크기 | 쓰임 |
| --- | --- | --- |
| `font.24lo` | 256×1024 | 페이지 0: 라틴 문자 |
| `font.24hi` | 256×1024 | 페이지 1 (원래 일본어) |
| `font.24lo2` | 256×1024 | 페이지 2 (원래 일본어) |
| `font.24hi2` | 256×1024 | 페이지 3 (국기·아이콘·대문자 사본 등) |
| `font.12lo`/`12hi` | 128×512 | 소형 |

한 칸은 24×32, 한 줄에 10칸. 문자열 안의 `0x01`/`0x02`/`0x03` + 코드 바이트가 페이지 1/2/3의 글자이며, 칸 번호 = 코드 − 6입니다. 한글은 이 방식으로 넣었습니다.

- 페이지 1·2 전체와 페이지 3에서 원래 그림이 없는 칸에 한글을 그렸습니다(공백 0x20, 줄바꿈 0x5C, 마크업 0x7E 코드는 쓰지 않음). 쓸 수 있는 칸은 592개입니다.
- 페이지 3에서 그림이 있는 칸(국기, 버튼, 드라이버 카드에 쓰이는 대문자 사본 등)은 원본 그대로 둡니다.

## 코드 패치 (GAME.CGO 안 `font`, `font-h`)

1. **소형 글꼴의 한글 페이지**: 문자열 출력 루틴 4곳에서 소형 글꼴일 때 페이지 1~3 템플릿을 읽는 `lq t2/t3/t4, 0xd0/0xe0/0xf0(v1)`을 대형 템플릿 `0x110/0x120/0x130`으로 바꿨습니다(소형 페이지 1~3 텍스처가 없음).
2. **효과 문자열 출력기**(GOAL로 작성된 별도 루틴, 레이스 일시정지 메뉴 등): 원래 `0x01~0x03` 접두를 만나면 페이지 템플릿을 바꾸지 않고, 접두 다음 바이트를 한 번 더 그리며, 글리프 표 포인터를 누적해 망가뜨렸습니다. 접두일 때 템플릿 포인터(`s3`)에 페이지×16을 더하고 문자열 포인터를 2바이트 넘기도록 고치고, 표 포인터 누적 저장을 없앴습니다. 소형 템플릿 복사(`ld 0xd0~0xf8`)도 대형으로 바꿨습니다.
3. **자간**(`font-h`의 `font-work`): 고정폭 페이지의 글자 전진 폭을 소형 16→13, 대형 32→26으로 줄였습니다.

바꾼 명령은 `tools/build.py`의 `patch_cgo`에 원본 바이트 패턴과 함께 적혀 있으며, 패턴이 정확히 한 번(또는 정해진 횟수) 나오는지 확인한 뒤 적용합니다.

## ISO 기록

원본 ISO를 복사한 뒤, 바뀐 파일이 원래 자리(다음 파일 시작 전까지)에 들어가면 그 자리에, 아니면 디스크 끝에 덧붙이고 ISO9660 디렉터리 레코드의 LBA·크기를 고칩니다. 원본 디스크에 끝부분 여유가 있어 결과 ISO 크기는 원본과 같습니다.
